# 2026.320.2222 — fix(require): advance the pod-marimo pin past the CDI driver-shadowing fix

## Summary

`pod-marimo` v2026.290.2104 → **v2026.320.2210**, producer-first — that tag landed as
opencharly/pod-marimo#10 before this pin moved.

**Why one line here breaks a whole project's gate.** The old `pod-marimo` still requires
`layer-cuda v2026.290.2052`, and *that* still requires the pre-fix `layer-nvidia` commit:

```
box/versa
  ├── pod-airflow  <-- this pin
  │     └── require: pod-marimo:v2026.290.2104
  │           └── require: layer-cuda:v2026.290.2052
  │                 └── require: layer-nvidia:7766a9d06ec5…      <-- pre-fix
  ├── pod-marimo:v2026.320.2210                                   <-- conflict: two refs
  └── layer-cuda:v2026.320.2103 + layer-nvidia:v2026.320.1938     <-- two more
```

so a box that composes both this pod and the current GPU stack resolves three candies at two
refs each, and charly refuses the project:

```
candy github.com/opencharly/layer-nvidia resolved to multiple git tags with differing content
within one scope (box=versa); using newest referenced v2026.320.1938 (from …);
also referenced 7766a9d0… (from …; scopes: box=versa)
```

That diagnostic exists in that shape only because opencharly/sdk#549 landed today; before it the
message named the winner alone, and finding this two-hop `require:` chain meant bisecting an
eighteen-candy box one candy at a time.
